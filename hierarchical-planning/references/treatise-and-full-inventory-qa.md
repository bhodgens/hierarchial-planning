# Treatise input + full-inventory Q&A

Addendum to `references/gap-analysis-forest-pattern.md` (2026-08-29).

## Treatise vs competitor report

An agent-engineering **book/course/treatise** (example: bojieli/ai-agent-book)
is a diagnostic, not a feature mine. Do not port companion experiments,
in-process SFT/RL, or a clone of the author's reference agent. Map chapters
onto existing surfaces. SKIP ideas that belong outside this runtime.

Meept-specific method + inventory: meept-design
`references/agent-book-harness-audit.md`.

## Agreement is not a design answer

"I agree with all gaps / benefits / deficiencies — make the plan" accepts
*whether*. It does not answer *how* (package home, default-on vs opt-in,
which surfaces, skip training, isolation defaults).

Still run Phase 3 Q&A. Offer "all recs" as a valid one-line reply.
Do not write plan files until that reply (or numbered overrides) lands.

## Full inventory, not the review summary

If the user says "cover all significant points, not just those summarized,"
the Q&A and later forest must list every Do-now / Do-next / Later / Skip
item from the analysis. The summary is for the human. The plan is for
implementers.
