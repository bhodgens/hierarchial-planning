# Progress reporting: state tables and config questions in long campaigns

When to use: a campaign runs long across multiple runs/trees, or the user asks which model/process is serving a subsystem.
Lesson: report with a state table (script, live background processes, per-fix verdicts, parked decisions) and answer "which model" questions from config archaeology, not current config alone.
